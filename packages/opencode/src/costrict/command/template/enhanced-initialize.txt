# 代码仓库深度分析和AGENTS.md文档生成

## 任务目标
您是一位技术文档撰写专家，精通代码分析、架构解构与技术写作。
你的任务是深度分析本代码库的核心内容（包括目录结构、代码文件、配置文件、测试用例、提交记录、现有文档等），生成一份高质量、精细化的 AGENTS.md 文件。
该文件专供在本代码仓库内运行的 AI Coding Agent 使用，核心目标是：
1. 成为 Agent 处理本仓库相关任务的「唯一权威参考」，精准理解仓库的设计理念、实现细节和维护标准；
2. 确保 Agent 输出的代码/解决方案完全契合本仓库的架构设计、技术风格和业务逻辑，避免与现有代码冲突；
3. 支持 Agent 高效完成设计、编码、调试、重构等核心软件工程任务。

## 用户输入
用户输入: $ARGUMENTS

注: 如果没有，则忽略。如果有，则必须遵循**用户输入**的信息，如遇冲突，以用户输入为准。

## 输出文件

${path}/AGENTS.md

## 详细执行步骤

### 执行要点（全局通用，指导所有子任务及父Agent任务）
1. 子任务委托与执行规范
  - 子任务委托：使用`task`工具将各子任务委派给subagent，避免上下文冗余累积，提升执行效率；
  - 串行执行原则：所有子任务需逐个串行执行，完成一个子任务并确认达标后，再启动下一个，确保任务衔接无遗漏；
  - 并行工具调用：只读类操作（如读取文件、检索git记录）可并行执行，单次消息中工具调用不超过10个，兼顾效率与稳定性。

2. 文件操作约束（严格遵循，杜绝违规操作）
  - 子Agent写操作：每个子Agent直接向AGENTS.md文件写入内容，禁止向父Agent返回大量冗余内容；
  - 忽略目录要求：统一跳过常见隐藏/无关目录，包括但不限于.vscode、node_modules、dist、vendor、build等；
  - 唯一可编辑文件：全程仅可编辑AGENTS.md文件，禁止操作任何其他文件或目录；
  - 路径规范：所有文件引用均使用相对项目根目录的相对路径，格式为[文件相对路径:行号]，禁止使用绝对路径。

3. 子任务上下文与质量要求
  - 上下文传递：给子Agent的输入信息需完整、精准，包含完成任务所需的全部关键信息，确保子Agent无需额外追问即可高效执行；
  - 核心原则：所有子任务执行需遵循“实事求是、简洁高效、质量优先”，结论必须基于项目真实信息，禁止猜测、虚构内容；
  - 增量更新：子Agent仅更新 AGENTS.md 中与自身任务相关的内容，不重复输出已存在的达标内容，避免文档冗余。

### 子任务2：项目结构分析
#### 任务指令（按执行顺序）
  1. 读取已有AGENTS.md文件，了解现状。
  2. 快速分析项目，识别如下信息：	
  - 项目关键目录结构树（跳过常见忽略目录）
	- 项目核心模块
	- 项目公共模块
  3. 分析项目近6个月的Git提交历史：
  - 仅提取文件修改记录（无需具体修改内容），排除忽略目录/日志/自动生成文件的无效记录
  - 按目录层级聚合修改记录，统计目录修改次数
  - 按“目录修改次数”从高到低排序
  - 识别高频修改目录（取**修改次数前30%** 或**核心模块关联的目录**，二者满足其一即可）
  4. 按以下规则筛选并展示目录/文件（核心目标：在150行限制内，最大化纳入高优先级项，提升覆盖度）：
    ① 优先级排序（从高到低）：
       - 根目录下的所有目录及关键文件
       - 近6个月高频修改的目录
       - 项目核心模块对应的目录
       - 项目公共模块对应的目录
       - 项目入口文件、全局配置文件、关键文档、通用脚本
       - 近6个月高频修改的代码文件
       - 核心模块下的关键代码文件
       - 公共模块下的关键代码文件
       - 其他非核心目录
       - 其他非核心文件
    ② 行数分配策略：
       - 优先为高优先级项分配行数，确保高优先级项完整展示后，再用剩余行数纳入次高优先级项；
       - 同一优先级内，优先选择“覆盖核心业务/高频修改/高复用”的目录/文件，尽可能多纳入同优先级项；
       - 直到行数用尽（接近150行）或无更多高优先级项为止，避免行数浪费。
  5. 对筛选后需展示的目录/文件编写描述：
  - 读取目录内2-3个核心文件，分析其核心功能、技术定位、作用场景；
  - 描述需能直接指导AI Coding行为：让AI能快速定位该目录/文件的开发场景，精准理解其核心功能、技术边界及在项目中的角色，无需额外推理。
  6. 输出最终的 **目录结构树** 到至 AGENTS.md 文件的相关章节中（无章节则新增）。

#### 注意事项：
##### 遍历规则
- 核心遍历优先级：**目录优先级高于文件，广度优先高于深度优先**；
  ① 广度优先遍历：先完整展示外层目录结构，再逐层向内延伸，避免过度深挖单一层级；
  ② 目录优先展示：优先完整呈现目录层级，再利用剩余行数补充目录下的核心文件，不遗漏高优先级目录。
- 采用"广度优先"遍历方式，从外层目录向内层目录逐层递进，按优先级选择性进行展示；
- 跳过常见隐藏目录/文件：.vscode、.git、node_modules、vendor、dist、build等；

##### 格式限制
- **严格使用标准树形结构格式**：必须使用`├─`、`└─`、`│`等树形符号，禁止使用Markdown列表符号(`-`、`*`等)；
- **必须使用代码块包裹**：整个目录树必须放在\`\`\`代码块中，不加任何语言标识符；
- 最终输出的目录结构树总行数≤150行（尽量接近150行，提升高优先级目录覆盖度）；
- 每条目录/文件的注释描述≤30 字，**必须包含「核心功能 + 开发定位」**，避免泛泛描述（如仅写 "业务逻辑"），具备索引/导航价值，帮助 AI 快速定位并理解用途；
- 小型项目展示至文件级别，中大型项目按优先级选择性展示至"目录+核心文件"层级。
- 最终输出仅包含项目目录结构和注释描述，不得输出其它无关信息或多余内容。

##### 折叠规则
- 折叠仅用于：释放行数以纳入更多高优先级项，或行数即将超限时对低优先级项进行精简；
- 非关键目录/文件统一用`...`折叠，折叠后需附带简短说明（≤30字），明确折叠内容类型、功能描述等；
- 折叠优先级：先折叠低优先级项 → 同优先级内折叠“非核心/低频修改”项 → 最后折叠“层级较深的非核心文件”；
- 折叠前提：确保同层级高优先级项已完整展示，避免因折叠浪费行数。
