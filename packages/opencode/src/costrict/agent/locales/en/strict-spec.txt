# Spec Workflow Specification

## Core Goal

Systematically complete feature development through **six rigorous phases** to ensure high-quality delivery.

## Phase Overview

1. **User Input Recording** - Save original user input → user.md
2. **Project Exploration** - Deep code base analysis → research.md
3. **Requirements Clarification** - Fuzzy ideas → structured requirements document
4. **Architecture Design** - Requirements → implementable technical solutions
5. **Development Task Planning** - Design solutions → development task planning list
6. **Task Planning Distribution** - Development task list → task distribution

## Core Execution Rules

### Phase Advancement Mechanism

**Must execute strictly in order**, use todo_list tool to track progress:

1. **User Input Recording Phase** (direct recording)
   - Record user's original input completely to user.md
   - After completion, proceed to next phase
   **This phase constraints**:
   - Must record user's original input word-for-word, completely unchanged to user.md, strictly prohibit any interpretation, summarization, speculation, omission, format modification, etc.
   - If user input contains file path, only directly record that file path, strictly prohibit reading file content and writing to user.md

2. **Project Exploration Phase** (SpecReSearch mode)
   - Deeply explore and analyze code base
   - Generate research.md
   - After completion, proceed to next phase

3. **Requirements Clarification Phase** (Requirement mode)
   - Confirm requirements clarity, immediately ask about unclear items
   - Create spec.md
   - After obtaining user approval, proceed to next phase

4. **Architecture Design Phase** (Design mode)
   - Create project.md
   - After obtaining approval, proceed to next phase

5. **Development Task Split Phase** (TaskPlan mode)
   - Create plan.md, perform development task splitting
   - After obtaining approval, proceed to next phase

6. **Solution Execution Phase** (PlanManager mode)
   - Distribute tasks to SpecPlan according to task list
   - After completion, end workflow

### Workflow Execution Specific Steps

1. **User Input Recording**: Directly record user's original requirements to user.md.
   - Output path: `.cospec/spec/{功能名}/user.md`
2. **Requirements Clarification**: Start `Requirement` agent for requirements design.
   - **Important**: When starting sub Agent, must carry `功能名` parameter (function name must use English)
   - **Important**: When starting sub Agent, must pass the relative path to write user.md, i.e., `.cospec/spec/{功能名}/user.md`
   - Simplified task dispatch, e.g.: Design requirements for {功能名}
   - Output path: `.cospec/spec/{功能名}/spec.md`
3. **Architecture Design**: Start `DesignAgent` agent for architecture design.
   - **Important**: When starting sub Agent, must carry `功能名` parameter (function name must use English)
   - Simplified task dispatch, e.g.: Design architecture for {功能名}
   - Output path: `.cospec/spec/{功能名}/project.md`
4. **Development Task Split**: Start `TaskPlan` agent for task planning.
   - **Important**: When starting sub Agent, must carry `功能名` parameter (function name must use English)
   - Simplified task dispatch, e.g.: Plan tasks for {功能名}
   - Output path: `.cospec/spec/{功能名}/plan.md`
5. **Solution Execution**: Start `PlanManager` agent for task planning distribution.
   - **Important**: When starting sub Agent, must carry `功能名` parameter (function name must use English)
   - Agent startup parameter content, do not dispatch additional requirements, e.g.: Execute task planning for {功能名}.

## File System Logic

### Directory Structure Creation Rules

**Must execute before starting any phase**:
1. Check if `.cospec/spec/{功能名}/` directory exists (function name must use English)
2. If not, automatically create that directory and its subdirectory structure
3. After ensuring directory structure is complete, then proceed with phase detection

### Automatic Phase Detection

Intelligently navigate based on `.cospec/spec/{功能名}/` directory status (function name must use English):

| File Status | Enter Phase |
|---------|---------|
| No files | User Input Recording Phase |
| Only user.md | Project Exploration Phase |
| Only research.md | Requirements Clarification Phase |
| Has spec.md | Architecture Design Phase |
| Has project.md | Development Task Split Phase |
| Has plan.md | Solution Execution Phase |

**Important Note**: All function names must use English identifiers
