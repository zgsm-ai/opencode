## 阶段 3：需求澄清（clarify.md）

重点澄清模式 - 只澄清重要问题，细节问题自行决定

目标：将需求中的关键不确定点转化为结构化的"问题 - 回答"记录。clarify.md 是需求澄清的唯一真相源。本模式聚焦核心决策点，细节问题由开发者基于代码规范和最佳实践自行判断。

### 3.1 初始化问题清单

前置要求：只有通过阶段2的代码探索仍无法确定的重要问题，才能纳入问题清单。

操作步骤：
1. 创建 `proposal/[change-id]/` 子目录（change-id 应简短有意义，如 `evaluation-mode-cli`）
2. 创建 `proposal/[change-id]/clarify.md`，写入纯粹的问题清单
3. 调用 `show_markdown_to_user` 展示给用户

问题清单要求：
- 只写问题本身，禁止预设答案、默认值或推荐选项
- 禁止在问题后附加倾向性文字
- 每个问题必须说明探索发现

应纳入的重要问题：
- 核心功能的实现方式选择
- 关键架构决策（数据结构选型、模块边界划分）
- 用户交互流程的关键节点
- 兼容性和向后兼容要求
- 错误处理的主要策略
- 存在多种合理方案且影响较大的决策点

不纳入的细节问题（自行决定）：
- 命名规范 - 遵循项目现有风格
- 日志级别 - 按常规实践选择
- 错误提示文案 - 遵循清晰有帮助的原则
- 配置项默认值 - 选择合理的默认值
- 边界条件处理 - 遵循防御性编程原则
- 输出格式细节 - 遵循项目现有规范
- 超时时间、重试次数 - 使用合理的默认值

正确示例：
```markdown
## 需要确认的问题

### 1. 关于 evaluation 配置结构

问题 1.1：ground_truth_proposal 路径格式
- 探索发现：现有配置中路径格式不统一，无法判断应遵循哪种模式
- 待确认：应使用相对路径还是绝对路径？如果是相对路径，应相对于哪个目录？

问题 1.2：配置扩展性
- 探索发现：当前配置结构为扁平式，未见扩展预留
- 待确认：未来是否有扩展其他字段的规划？这会影响配置结构设计

### 2. 关于 CLI 参数

问题 2.1：参数作用范围
- 探索发现：现有参数分为全局参数和子命令参数两类
- 待确认：--evaluate-repo 应添加到哪些命令中？
```

错误示例（禁止）：
- 将细节问题纳入问题清单
- 没有说明探索发现，直接提问
- 问题可以通过阅读代码直接得到答案

### 3.2 与用户交互

交互方式：
1. 使用 `question` 工具提示用户查看问题清单
2. 每次提问可引用代码上下文帮助用户理解背景
3. 可在对话中提供示例或备选方案，但不写回问题文本

### 3.3 回填答案

用户回答后立即执行：
1. 使用 `str_replace_based_edit_tool` 的 `str_replace` 命令更新 clarify.md
2. 在对应问题后追加"回复"条目，保留原问题文本不变

要求：忠实记录用户原意，不擅自改写。

### 3.4 动态刷新问题

每当用户回答一个问题后：

1. 重新审视后续未回答的问题
   - 问题前提是否因当前答案而变化？
   - 是否暴露出新的重要不确定点？
   - 新暴露的问题是否真的重要？如果只是细节，自行决定即可

2. 更新 clarify.md
   - 不再适用的问题：删除或重写
   - 新的重要不确定点：追加（需先尝试通过代码探索解决）
   - 细节问题不追加，自行处理

禁止事项：
- 禁止机械地按初始列表问到底
- 禁止询问性能提升相关问题
- 禁止询问测试/验证相关事项

### 3.5 完成判断

clarify.md 完成的标准：
- 所有重要问题都有明确回复
- 不再存在关键疑问点
- 细节问题已有明确的处理方案

完成后调用 `show_markdown_to_user` 展示最终版，再进入阶段 4。

### 3.6 细节决策记录

自行决定的细节问题应在 proposal.md 的"实现细节说明"章节记录：

```markdown
## 实现细节说明

以下细节问题基于项目现有规范和最佳实践自行决定：

| 决策点 | 选择 | 依据 |
|--------|------|------|
| 配置项命名 | 下划线风格 | 与现有配置一致（见 config.py 第 45 行） |
| 日志级别 | INFO | 现有核心流程均使用 INFO |
| 错误提示格式 | 问题描述 + 建议方案 | 遵循 errors.py 中的现有模式 |
| 超时设置 | 30 秒 | 与现有网络请求超时一致 |
```

用户审阅 proposal 时可对这些决定提出修改意见。
