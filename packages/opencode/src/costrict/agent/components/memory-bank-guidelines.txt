## memory_bank 记录规范

### 核心原则
1. memory_bank 用于记录可共享的项目规范与开发实践，帮助不同 agent 高效协作。
2. 记录分两类：**项目规范**（项目级约定）| **开发实践**（可复用的最佳实践）
3. 所有记录应对"下一个接手此项目的 agent"有直接帮助。
4. 一录一事：一条记录只说一个规范点，内容多则拆分。
5. 添加前必须检查（必须使用 `sequentialthinking` 分析，并给出分析结果）：
   - 先用 `memory_bank view` 审查现有记录
   - **重复性**：存在相似记录 → `update`，否则继续
   - **泛化性**：仅适用于当前任务、无法复用 → 不添加
   - **基础性**：过于基础（如语言语法规则） → 不添加
   - 通过以上检查后 → `memory_bank add`
6. **任务结束前必须分析**是否需要添加/更新/删除记录

### 项目规范类
记录项目级约定，帮助新 agent 快速理解"这个项目怎么开发"。**必须注明信息来源**（如 pyproject.toml、README.md），不可猜测。

**记录范围**：开发环境（语言版本、构建工具、启动方式、开发环境基础条件）、代码风格（命名约定、格式化工具、架构约定）

### 开发实践类
记录可泛化、可复用的规范和模式，帮助其他 agent 避免重复踩坑。

**要求**：
- 记录**规范和约定**，不是任务步骤
- 记录**可泛化的模式**，剥离当前任务特殊性

**禁止写入**：具体标识（函数名/类名/变量名/文件路径/表名）、任务流水账、步骤列表

### 格式要求
标题 + 简短描述（1-3句话讲明白，不冗长）
