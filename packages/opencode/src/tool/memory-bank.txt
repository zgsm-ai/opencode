Memory Bank 工具，记录可共享的项目规范与开发实践，帮助不同 agent 高效协作。

【记录分类】
• 项目规范：开发环境、代码风格等项目级约定
• 开发实践：可泛化、可复用的最佳实践

【核心原则】
• 记录应对"下一个接手此项目的 agent"有直接帮助
• 只记录规范和约定，不记录任务步骤或流水账
• 剥离任务特殊性，提取可泛化的通用规范
• 禁止写具体标识（函数名/类名/变量名/文件路径等），需抽象化
• 一录一事，内容多则拆分
• 添加前先 view 检查，存在相似记录则 update

【命令】
• view: 查看全部记录
• add: 添加记录（需 tag, title, lesson）
• update: 更新记录（需 tag，可选 title/lesson）
• delete: 删除记录（需 tag）

【正确示例】
1. 项目规范 - 记录项目约定，注明信息来源：
   Tag: dev-setup | Title: 开发环境配置
   Lesson: 通过对pyproject.toml的分析，我发现这个python项目使用uv管理依赖（而不是pip），运行uv sync安装依赖；测试的时候使用pytest，代码检查使用ruff check + ruff format，在开发时应该遵守同一套规范。 

2. 开发实践 - 记录可复用的规范/模式：
   Tag: build-timeout | Title: Go构建超时降级策略
   Lesson: 经过验证，当前机器并没有网络连接，这会直接导致go build因为环境依赖不足而构建超时，因为网络问题是没法解决的，开发时应放弃完整构建，临时使用gofmt进行语法和类型检查，确保基础代码质量。同时需要告知用户所采取的降级策略。

【错误示例】
1. 任务步骤（错误）："第一步创建类，第二步实现方法..."
   → 这是流水账，不可复用。

2. 具体实现（错误）："在 UserService 类第156行修改 getUserInfo 方法..."
   → 包含具体标识，应抽象为"查询方法应先查缓存再查数据库"
