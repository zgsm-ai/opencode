将编码任务委派给子编码代理（SubCodingAgent）。

子编码代理将：
- 在隔离的上下文中执行分配的编码任务
- 使用 agent-git 进行版本控制（提交时以 agent_code 作为作者）
- 返回执行结果，包含反馈信息和 agent-git 统计数据

**重要事项：**
- 所有代码更改必须通过此委派工具进行
- 为每次调用分配唯一的代理代码（SubCodingAgent-1、SubCodingAgent-2，依此类推...）
- 必须等待当前 SubCodingAgent 完成后，才能分发下一个任务
- 在更新 task.md 之前，请先审查返回的 agent-git 提交记录以验证任务完成情况
- 只有在子编码代理成功完成任务后，才能更新 task.md

关键-任务粒度原则：
- 不要将不同阶段的任务放到一起
- 避免过多：过多任务可能超过工具调用预算，导致任务无法完成
- 避免过碎：过小的单个任务（如一行代码修改）会导致上下文割裂和低效
- 可完成性：确保任务可在工具调用预算内完成，为可能的探索和调试留出余量

关键-任务原文一致性：
- 当任务来源于 task.md 时：允许为每条任务拟定概括性的 title，但 detail 必须包含原始任务条目中的所有具体信息（修改对象、修改目的、修改内容），不得压缩、删减或改写导致信息丢失。
- 如需补充主 Agent 新发现的信息，请放到 important_note 而不是 detail。
